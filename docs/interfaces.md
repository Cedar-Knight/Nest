# 交接接口草案 v0

状态：供P1讨论与实现使用，尚未实现校验器或冻结协议。示例位于 [examples/handoff](../examples/handoff/README.md)，均为人工样例。

## 任务

包含 `schema_version`、`task_id`、`robot_id`、`round_id`、`type`、区域或目标、观察参数和返航条件。坐标必须注明坐标系、单位与地图版本；首版样例使用显式给定位置。

## 返回记录与接收

记录包含关联任务、观测类型、时间基准、文件相对路径、字节数及SHA256、执行状态和异常。所有路径限制在该任务目录；不接受绝对路径或越界路径。

建议状态：待执行 → 已记录 → 交接中 → 完整接收；失败可重试。传输完成需要完整文件校验及母巢接收确认，复制开始不算成功。源文件在确认前保留，确认后的保留策略仍待确定。

重复收到同一任务／记录与同一校验值时返回已有凭据，不重复创建候选或复核任务；相同编号却内容不同应报告冲突。断连重试、重启恢复与接收确认的持久化须在P1验证。

## 候选入口与判定

包含候选编号、位置、地图版本、证据来源、事件编号、时刻与方向、有效观察时间和数据质量。只有真实出入事件参与5次／180秒判断；相同秒不同事件不能仅凭时刻去重。

输出区分 `rule_confirmed`（规则确认）、`unconfirmed`（有效观察内未达到门槛）、`insufficient_data`（观测质量、同步或位置不足）。规则确认不是实际巢穴证明，也不是独立真值。

## 下一轮复核

生成任务必须引用已接收记录、候选入口及位置；无可执行位置时转人工检查。P1使用人工事件适配器，不声称视觉识别或地图生成已经实现。搜索轮形成候选后安排复核，复核结果回指同一候选。未确认或数据不足时的重访策略由负责人选择。

## 尚需决定

存储保留周期、重试上限、任务取消／失败策略、真实时钟同步误差、地图修订后目标变换与坐标容限。先确定影响P1的状态与恢复规则，硬件相关参数留到P2。
